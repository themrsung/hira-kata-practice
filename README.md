# hira·kata practice

A stateless single-page kana drill. Practice **hiragana → katakana**, **katakana → hiragana**, or
random, and answer with real Japanese keyboard key positions — not a multiple-choice quiz.

**Live: https://hirakata.sjun.me**

## Why key positions

Kana keys are script-independent. The same physical key types か or カ depending on IME mode, so a
kana drill really tests *sound → key position*. This app keys everything off
`KeyboardEvent.code` (the physical position), which is layout-independent — so US-ANSI and JIS
hardware both work without remapping anything.

## Input modes

| Mode | What you type |
|---|---|
| **US ANSI kana** | JIS kana layout mapped onto a 104-key ANSI board |
| **JIS kana** | The real 106-key JIS kana layout, including `¥`/`ー` and `IntlRo`/`ろ` |
| **Romaji** | The reading itself (`kya`, `shi`/`si`, `tsu`/`tu`, … alternates accepted) |

### The ANSI problem, handled

A JIS board has two keys ANSI physically lacks: `IntlYen` (ー) and `IntlRo` (ろ). On the ANSI board
those two keys are rendered greyed out and **Backslash is accepted as the stand-in for ろ**. That is
unambiguous here, because the drill always knows which single kana it is asking for.

The two boards also differ in where `Backslash` physically sits: on JIS it is at the end of the home
row (right of `'`), on ANSI it is at the end of the QWERTY row (right of `]`, above Enter). Each
board renders its own row order.

## Character sets

Gojūon (あ–ん), dakuten (が ざ だ ば), handakuten (ぱ ぴ ぷ), small kana (ぁ っ ゃ), and yōon
digraphs (きゃ しゅ). Toggle any combination.

Multi-key sequences are derived, not hardcoded: dakuten/handakuten forms are decomposed with Unicode
NFD, so じょ is correctly `し` + `゛` + `ょ` — three keystrokes.

## Assists

- **Keyboard** — on-screen board showing kana legends and Latin legends per layout.
- **Hint** — highlights the next required key, one keystroke at a time (one letter at a time in
  romaji mode).
- **Rōmaji** — prints the reading under the prompt. Hidden in romaji input mode, where the reading
  *is* the answer.
- **Key legends** — the board is labelled in katakana by default; switch to hiragana if you prefer.
  Kana mode only, since romaji mode shows Latin legends anyway.

## Stateless

Nothing is stored — no account, no localStorage, no cookies. Your settings live in the URL hash, so
a configured drill is just a link:

```
/#d=h2k&i=jis&kb=1&kl=k&h=1&r=1&c=gojuon.dakuten.yoon
```

`d` direction (`h2k` | `k2h` | `random`) · `i` input (`ansi` | `jis` | `romaji`) · `kb` keyboard ·
`kl` key legends (`k` katakana | `h` hiragana) · `h` hint · `r` rōmaji reading ·
`c` dot-separated character sets.

## Corpus

The kana table is a plain TSV text source at `src/data/kana-corpus.tsv` (118 entries), generated by
`scripts/generate-corpus.mjs`. Katakana is derived from hiragana by the fixed +0x60 codepoint
offset, which holds across the whole U+3041–U+3096 block.

```bash
npm run corpus   # regenerate the TSV
npm run dev
npm run build
```

## Stack

React 19 + TypeScript + Vite. No runtime dependencies beyond React.
